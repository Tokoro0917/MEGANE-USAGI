# 仮想ライントレース（最終目標）

**最終的に、仮想ライントレースで走る**（2026-10-21）。

## 仮想ライントレースとは

1. **1 走目（探索）**: ラインをトレースしながら、エンコーダとジャイロで自分の位置（X, Y, 向き）を計算し、**数 cm ごとの座標でコースの地図** を作る
2. **走行の合間**: 地図を補正し、ラインから外れすぎない範囲で **最短・最速の経路** と速度の計画を作る
3. **2 走目以降**: ラインではなく **自分で作った仮想の経路** を、自己位置推定と経路追従（Pure Pursuit など）で走る。ラインのショートカット（Out-In-Out）ができる

上位機の例（[survey.md](../survey.md)）:
- **VLT-2**（関西 2025 で 3 位、96g、2S）: 1 走目に 2cm ごとの XY 座標で地図を作り、2 走目は仮想の目標点を pursuit で追う
- **APOLLON**（全日本 2025 優勝）: 数理最適化で Out-In-Out の経路を作り、曲率が大きすぎるショートカットは避ける
- **L1S** など: ラインから外れない範囲でショートカットする
- 社畜博士のロボット工作室（ロボトレース 2023 / 2024）: 1 周目の XY 座標から最適経路を作り、自己位置推定で仮想ライントレースする。**移動平均で滑らかにした経路でも 8 割くらいの効果がある** ので、仮想経路の追従は後から実装するのがよい、とのこと。ジャイロの値のずれでオドメトリが狂ったことも書かれている
  - http://www.ak-rcroom.com/sakuhin/robotrace/robotrace_2023/
  - http://ak-rcroom.com/sakuhin/robotrace/robotrace_2024/robotrace_2024/

## 規定との関係: どこまでショートカットできるか

- 規定 3-1: 「ロボトレーサの床面投影が常にライン上にある」こと。**機体の投影がラインから完全に離れるとコースアウト**（[rules.md](../rules.md)）
- → 機体の **どこか一部** がラインにかかっていればよい。ショートカットできる幅は **機体の横幅で決まる**
  - 例: 幅 150mm（ラインセンサの列＋マーカーセンサ）なら、機体の中心はラインから最大 ±約 84mm（75mm ＋ ライン幅の半分 9.5mm）まで離れられる
  - 直径 25cm の円に収まる範囲で、幅 240〜250mm と申告している上位機（VLT-2、APOLLON など）は、**ショートカットの幅を広げるため** と考えられる
- 実際には、位置推定の誤差の分だけ余裕を残す（ラインの端ぎりぎりは走らない）

## 今の設計への影響

| 項目 | 必要なこと | 今の設計 |
|---|---|---|
| オドメトリ（距離） | 車輪の回転を正確に測る | MES-6-120PC を車軸で読む。1 カウント 0.157mm（[encoder.md](encoder.md)） |
| オドメトリ（向き） | ジャイロの値のずれ（バイアス）が小さいこと | LSM6DSR。**走る前に止まった状態でバイアスを測る**。温度でずれるので、走行の直前に測り直す |
| 車輪の滑り | 滑るとオドメトリが狂う | 吸引でグリップを上げる。加速度をグリップの上限より下に抑える |
| 機体の横幅 | 広いほどショートカットできる | ラインセンサの列は約 150mm。**横幅を広げるか（羽根のような細い部材など）は、重さ（100g 以下）とのかね合いで決める** |
| 位置の補正 | ラインセンサでラインとのずれを測り、地図と比べて位置を直す | ラインセンサの列（14 個、幅約 91〜98mm）がラインにかかっている間は測れる |
| 計算とメモリ | 地図（60m を 2cm ごと = 3,000 点）、経路、速度計画 | STM32H725（550MHz、RAM 564KB）で足りる。1 点 16 バイトでも 48KB |
| ログ | 1 走目の地図と、2 走目の位置推定を記録して PC で見る | 内蔵 Flash ＋ PC 側のツール（`tools/`） |

## 地図の補正（ループの閉じ方）

オドメトリは走るほど誤差がたまるので、コースの性質を使って補正する。

- **スタートとゴール**: どちらも同じ直線上にあり、間は 1m（規定）。1 周したら位置が合うはず
- **交差点**: 同じ地点を 2 回通る。2 回の座標が一致するように補正する
- **マーカー**: 曲率の変化点の位置。2 走目では、マーカーを検出した時点で地図上の位置に合わせ直す

## 段階的な進め方

[strategy.md](../strategy.md) の Lv1〜Lv5 のあと、**Lv6** として取り組む。関西で完走するのには必要ない。

| 段階 | 内容 |
|---|---|
| 準備（Lv1 から） | **最初から、走行中の位置（X, Y, 向き）を計算してログに残す**。完走を目指す段階のデータが、オドメトリの精度の確認に使える |
| 6-1 | 1 走目の地図を PC に吸い出して描く。実際のコースの図面と重ねて、誤差を確かめる |
| 6-2 | 地図を補正（スタート/ゴール、交差点）し、移動平均などで滑らかにした経路を作る |
| 6-3 | 2 走目で、滑らかにした経路をラインの代わりに追う（Pure Pursuit など）。ラインセンサとマーカーで位置を直しながら |
| 6-4 | 機体の幅とグリップ（摩擦円）を制約にして、経路と速度を最適化する |

## 決めること

- 機体の横幅（ショートカットの幅）と重さのかね合い
- 地図の点の間隔（2cm など）
- 経路を作る計算を、機体の中でやるか（走行の合間に）。規定 3-8 で、コース公開後にコース情報を入力することは禁止なので、**PC で計算した経路を書き込むことはできない**。機体の中で計算する必要がある
